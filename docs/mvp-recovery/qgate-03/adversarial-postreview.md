## Verdict classification opinion

Downgrade to INCONCLUSIVE. What the builder actually read is: one run, attempt 1, on the intended runner label; integration step success (a near-vacuous fact, since the script exits 0 on every path); and an annotation reading `capture overall=BLOCKED`. By the script's own rule that does imply no check FAILed and the primary (not the 2751) record is the one read, and by the script's control flow the record was written only after the ingress printed READY. But `overall=BLOCKED` is equally what the script emits when the capture raised, when Yama is absent, when ACL xattrs were unreadable, or when a tool was missing, and none of the check results, `profile_supported`, PASS count or BLOCKED ids were read. "HOST CANDIDATE — REMAINING GAPS" asserts a positive shape (a named list of gaps) that the run evidence does not support; the gap list comes from the design and an unrelated sandbox dry run. The host-verdict's own fallback sentence already concedes this. Recommended: record INCONCLUSIVE (per-check results UNREAD), carry "platform host candidate" forward only from QGATE-02 as the operator stated, re-derive after the operator attaches artifact 13023553992, and disarm the branch trigger before merge.
