## 1. Method and sources

`tools/scanner_tree_analysis.py` (with `tools/scanner_analysis_model.py`, tested in `tests/test_scanner_analysis.py`) lists tracked files with `git ls-files` in each pinned checkout, applies one file selection to all scanners (binary suffixes, NUL bytes and non-UTF-8 files are skipped; the scanner's own allow-list file is skipped), runs the verifier and ergonomics `scan_text`, runs the analysis model, runs each repository's own claim-boundary command once, and applies that tree's allow-list exactly (excluded paths; excusal by path, rule and exact line text). It writes nothing but stdout, opens no network connection and runs with bytecode writing off. The roots must be trusted pinned checkouts because the scanners' modules are imported.

The analysis model is **not a scanner**. It implements the proposals N1 to N4 so their effect can be measured before any behavior is frozen: N1 rule union without the deferred `safe` alternative, N2 fold pipeline, N3 dual view plus underscore view, N4 comment text scanned separately. It is wired into no gate.

## 4. Compatibility findings for review

**N2, fold pipeline (validate newly detected and lost matches).** Lost matches against the verifier or ergonomics scanners: none, apart from the deferred S-02 cases that appear only in this step's own text. Newly detected matches relative to one scanner or the other: the eight fixture lines in the verifier tree, the three fixture lines and one prose line in the ergonomics tree, and this step's own quoted test text in the hub; nothing else in real text. One regression was found in my own model during the run and fixed before these counts: removing backslashes (S-08) hid claims inside source strings such as `"certified\n"`; the model now reads literal `\n`, `\r` and `\t` as spaces first. The same blind spot exists in the ergonomics scanner (T-01), so N2 as proposed for the backslash step needs that ordering rule written into the normative text. Limits: three trees and a 178-case corpus, not a proof of no loss.

**N3, markup (regression checks).** Checks run: the full corpus differential (#205), the model unit tests (`tests/test_scanner_analysis.py`: markup, underscore, `__x__`, `_x_`, unknown tags such as `a<b certified c>d`, escaped whitespace) and the three tree runs. No match present in the verifier or ergonomics output on these trees disappeared. The underscore view adds `_certified_` and `__certified__`, which both scanners miss today (S-07).

**N4, HTML comments (hidden-source claims versus visible assertions).** The model scans comment text separately and reports `hidden_comment` only when the same line and rule has no visible match. Result: one `hidden_comment` finding in the hub's own corpus and none in the three trees' real text. So on these trees N4 changes no pass/fail result. The ergonomics scanner would delete such a claim in both views today (S-06).

**N5, hub scanner.** Deferred as instructed. Its different mechanism (negation-aware matching, a 67-key table with a different effective sigma result) is untouched and not modeled. A separate compatibility review is the next gate for it.
